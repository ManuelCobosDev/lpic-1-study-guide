## 1. Resumen Ejecutivo
El subtema 102.6 (Linux como sistema virtualizado, Peso 1, Páginas 161–183) cuenta con una implementación web de alta calidad didáctica y técnica (19 diapositivas estructuradas y un laboratorio interactivo de 4 misiones). Cubre con rigor los hipervisores KVM/QEMU/libvirt, las extensiones de procesador vmx/svm en /proc/cpuinfo, los formatos de almacenamiento RAW frente a QCOW2, el aprovisionamiento cloud-init con #cloud-config, y la seguridad con claves SSH. Las omisiones detectadas respecto al manual oficial son puntuales: falta el comando 'dbus-uuidgen --get' (respuesta directa del ejercicio guiado 3 del PDF), la mención explícita a 'Guest Extensions' (controladores empaquetados como las Guest Additions de VirtualBox vía CD-ROM ISO), el concepto de 'Híbrido' (virtualización completa con VirtIO), y la definición formal de 'migración en vivo' (live migration). En el ejercicio guiado 3 de la web se sustituyó la pregunta oficial sobre 'dbus-uuidgen --get' por 'systemd-machine-id-setup'. Veredicto: APTO_CON_HUECOS (85.6/100).

## 2. Qué falta en la Web respecto al PDF Oficial (7 ítems)
- **[command]** `dbus-uuidgen --get` (pág. 172): Comando para consultar y visualizar la ID actual de máquina D-Bus sin modificarla. Es la respuesta exacta al Ejercicio Guiado 3 del manual oficial (pág. 181).
- **[flag]** `--ensure=/etc/machine-id` (pág. 173): Sintaxis 'sudo dbus-uuidgen --ensure=/etc/machine-id' para forzar la regeneración del ID apuntando directamente al archivo /etc/machine-id tras su borrado.
- **[term]** `Controladores de la máquina huésped / Guest Extensions` (pág. 165): Término explícito en la lista de objetivos LPI (Partial Terms). En el PDF se describen los controladores empaquetados que proporcionan las plataformas como las 'Guest Additions' de Oracle VM VirtualBox distribuidas mediante imagen ISO de CD-ROM.
- **[term]** `Invitado Híbrido (Hybrid Guest)` (pág. 165): Concepto del PDF que define la combinación de virtualización completa con controladores paravirtualizados (VirtIO) para lograr rendimiento de E/S casi nativo.
- **[term]** `Migración en vivo (Live Migration)` (pág. 164): Definición del proceso de mover una máquina virtual en ejecución entre hosts físicos sin interrupción perceptible del servicio.
- **[term]** `Contenedor de aplicaciones vs Contenedor Linux` (pág. 176): El temario oficial LPI lista específicamente 'Contenedor de aplicaciones' (Docker/Podman centrado en aislar una única app) junto a 'Contenedor Linux' (LXC/LXD como contenedor de sistema completo).
- **[command]** `lsblk` (pág. 171): Comando mostrado en el PDF para contrastar la vista interna de particiones del disco virtual (/boot, swap, lvm) con el tamaño del archivo QCOW2 en el hipervisor.

## 3. Qué se ha puesto de más en la Web / Contenido Autor (4 ítems)
- **[command]** `systemd-detect-virt`: Comando de systemd enseñado en el laboratorio para detectar automáticamente si el sistema corre sobre hipervisor o contenedor (-c).
- **[command]** `virsh destroy / virsh undefine`: Distinción avanzada entre apagado forzado por hardware (destroy) y eliminación de la definición de dominio (undefine).
- **[command]** `truncate -s 0 /etc/machine-id`: Método estándar moderno de systemd para vaciar el archivo machine-id dejando el archivo a 0 bytes en la plantilla dorada.
- **[command]** `timedatectl / /etc/timezone`: Práctica de sincronización NTP y configuración de zona horaria incluida en el laboratorio 102.6.

## 4. Imprecisiones o Contradicciones Detectadas (2 ítems)
- **[P1]** `Ejercicio Guiado 3 (Diapositiva 14 vs PDF pág 178/181)` (pág. ?): El ejercicio oficial 3 plantea: 'Dos máquinas virtuales clonadas con D-Bus funcionan de manera irregular... ¿Qué comando se usaría para determinar si cada una tiene diferentes ID de máquina D-Bus? -> dbus-uuidgen --get'. La web lo sustituyó por la pregunta de '¿Qué comando se utiliza para regenerar el identificador con systemd? -> sudo systemd-machine-id-setup', perdiendo la pregunta original sobre D-Bus.

El manual oficial LPI señala con mayor matiz que KVM actúa tanto de Tipo 1 como de Tipo 2 porque necesita una base de sistema operativo Linux pero se integra en el kernel para ejecutar como hipervisor nativo.
