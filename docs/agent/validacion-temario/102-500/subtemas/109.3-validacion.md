## 2. Qué falta en la Web respecto al PDF Oficial (19 ítems)
- **[command]** `hostname` (pág. 450): Utilidad oficial del temario para inspeccionar y fijar temporalmente el hostname del sistema en tiempo de ejecución.
- **[flag]** `traceroute -i <interfaz>` (pág. 469, 476, 482): Opción imprescindible para forzar a traceroute a emitir las sondas a través de un adaptador de red específico (Ejercicio de Exploración 4).
- **[flag]** `traceroute --mtu` (pág. 482): Opción para descubrir y reportar el tamaño de MTU en cada salto del recorrido hacia el destino (Ejercicio de Exploración 5).
- **[flag]** `traceroute -I / -T / -n` (pág. 469, 477): Modificadores para enviar paquetes ICMP Echo (-I) o TCP SYN (-T) en vez de UDP, y omitir la resolución DNS inversa para una salida numérica inmediata (-n).
- **[flag]** `tracepath -p <puerto>` (pág. 471): Opción para fijar el puerto UDP base en el rastreo no privilegiado y detección de Path MTU (PMTU).
- **[flag]** `netcat -l -p <puerto> / -z / -v / -u` (pág. 472, 477): Parámetros fundamentales de nc: modo escucha (-l -p), escaneo de puertos sin transmisión de datos (-z, zero-I/O), modo detallado (-v) y modo UDP (-u).
- **[flag]** `ss -tulnp / ss -ln` (pág. 473-474, 479-480): Combinaciones estándar LPIC-1 para auditar sockets: TCP (-t), UDP (-u), en escucha (-l), numérico (-n) y con PID/nombre de proceso (-p).
- **[command]** `lsof -Pi:<puerto>` (pág. 479-480): Herramienta explicada en los ejercicios guiados 3 y 4 para inspeccionar qué proceso y PID tiene abierto un socket en un puerto concreto (ej. TCP 80 o TCP 22).
- **[flag]** `ip link add link ... type vlan id <id>` (pág. 465): Sintaxis para crear subinterfaces virtuales de etiquetado 802.1Q VLAN con ip link (Ejercicio de Exploración 1).
- **[flag]** `ip link add link ... type bridge priority <val>` (pág. 466): Sintaxis para configurar opciones de árbol de expansión (STP) y bridges de red con ip link (Ejercicio de Exploración 5).
- **[command]** `ip route save / restore` (pág. 465): Comandos para respaldar la tabla de enrutamiento a un archivo binario y restaurarla posteriormente (Ejercicio de Exploración 4).
- **[flag]** `route add default gw <ip>` (pág. 454, 465): Sintaxis heredada para configurar la puerta de enlace predeterminada en la tabla de rutas del kernel.
- **[path]** `/sys/class/net` (pág. 463): Ruta en sysfs para enumerar las interfaces de red detectadas por el kernel ('ls /sys/class/net', Ejercicio Guiado 1).
- **[path]** `/proc/net/` (pág. 473): Estructura de archivos de procfs parseada por netstat, contrastada con la interfaz netlink de alto rendimiento utilizada por ss.
- **[term]** `Path MTU Discovery (PMTU)` (pág. 471, 480): Mecanismo para determinar la MTU más pequeña a lo largo de una ruta de red con tracepath para evitar la fragmentación de paquetes.
- **[term]** `Recv-Q y Send-Q en ss` (pág. 474): Métricas de colas de sockets: paquetes recibidos por el socket pendientes de lectura por el proceso (Recv-Q) y bytes en cola para ser transmitidos (Send-Q).
- **[term]** `Banderas de enrutamiento (Flags U y UG)` (pág. 454, 464): Significado de las banderas en la tabla de rutas de netstat/route: U (Up/Ruta activa), G (Gateway/Pasarela) y UG (Ruta por defecto).
